# Privacy & security

**Your data stays yours.** Chirp has no cloud, no account and no telemetry: your own machine is the server (a Mac, a Windows PC or a Linux box), and audio and text only ever move between your own devices over your own tailnet. This page lists exactly what is kept, what is sent and where. Each component README has its own, more detailed privacy section: [server](../server/README.md#privacy-and-debugging), [Mac](../mac/README.md) (Live Notes → Privacy), [desktop](../desktop/README.md) (Linux and Windows), [Android](../android/README.md#privacy) and [iOS](../ios/README.md#privacy--security). The binding rules are in [architecture.md](architecture.md).

- **Dictation audio is transient; Mac and Android dictation history is local, sealed and on by default.** Dictation audio lives in memory for the utterance and is never kept. Mac, Android and iOS notes save continuously to a local library on the device that recorded them, kept forever by default (an earlier mobile opt-out stays off), with no Save step. Kept audio is opt-in and off by default. On the Mac, dictation history is on by default (below); Android history is also on by default with separate retention (an explicit off choice stays off); iOS history stays opt-in (off until you turn it on, then 7 days by default). iOS keeps an AES-GCM sealed Notes library and AES-GCM encrypted transient app↔keyboard mailbox text (deleted on consumption or expiry at next access). Logs carry only timings, byte counts and error codes. There is no telemetry.
- **Mac dictation history stays on this Mac, encrypted.** Every committed dictation is kept so you can find, copy or insert it again: the inserted text, the raw transcript when clean-up changed it, the app it went to (bundle id and name), the time, its length and the clean-up style. It is never kept for a password field (secure input or a secure text field), a cancelled dictation, or an app on Settings → History & privacy → **Never keep** (password managers by default). Entries live under `~/Library/Application Support/Chirp/History/`, one file per day, each AES-GCM sealed with a 256-bit key held in this Mac's Keychain (service "Chirp Dictation History", not synchronizable; `ThisDeviceOnly` where the build may use the data-protection keychain, else the login keychain, which iCloud Keychain never syncs). The folder is `0700`, files are `0600`, Spotlight is told never to index it, and nothing is synced, uploaded or logged. A file whose key is gone is deleted, never repaired. Retention is 30 days by default (1, 7, 30 or 90 days, or forever). **Clear…** deletes every file and the key; turning history off asks whether to delete what is kept. The first-run window says history is on and where to turn it off.
- **Learn from my edits (Mac) stays on this Mac too.** While history is on, Chirp watches the field a dictation went into (through the Accessibility access it already has; Chromium and Electron apps are asked to expose their fields with `AXManualAccessibility`) until focus moves, the text around the dictation changes, 60 seconds pass or the next dictation starts, and only reads that field's text, never a password field or an excluded app. The log says only why a watch started, ended or was skipped, with the app's bundle id and counts, never the text. A fix made twice (or once with **Teach Chirp…** in History) becomes a learned item: one of your terms and the phrase it was heard as, or an app's style preference with a short before/after example. Items are sealed like the history in `~/Library/Application Support/Chirp/Learned/learned.sealed`, with their own Keychain key ("Chirp Dictation History", account `learned-key-v1`), never synced or logged. Active items go with each dictation's `start` to your own Chirp server (and, like the transcript, to the clean-up host if you configured an external one); they never make clean-up add words. Settings → History & privacy → **Learn from my edits** turns it off, and **Show Learned…** lists every item with Approve, Undo, Delete and Reset per app.
- **Live Notes stay on the device that records them.** Mac notes live under `~/Library/Application Support/Chirp/Notes/<uuid>/note.json`, with a lightweight `index.json`; folders are 0700 and files 0600. These files are not encrypted by Chirp. Notes are never indexed by Spotlight, synced or logged. Exporting Markdown makes a separate user-chosen copy and does not remove the library note. Existing Recovery journals migrate once. Retention defaults to Never, independently of dictation history; deletion moves notes to Recently Deleted for 30 days before permanent removal. Optional **Keep audio with notes** (Settings → Notes) defaults off and keeps mono AAC segments locally in each note’s `audio` folder, so a transcript paragraph can be replayed. Settings → Notes shows the total with **Delete…**, and each note shows its own size. Turning it off stops future audio storage; deleting existing kept audio is a separate operation that preserves text. Kept audio is never automatically uploaded. **Re-transcribe…** (a note’s menus, with **Settings → Notes → Allow re-transcribing**, on by default, as the off switch) sends a note’s kept clips only to the Mac’s configured Chirp server, after a confirmation sheet every time that names the length, the clip count and the destination; they are decoded in memory, sent over the existing authenticated socket, transcribed in memory there and not kept (unless the server keeps debug recordings, which the sheet warns about in red). The previous transcript stays with the note for **Undo** and **Restore Previous Transcript**; logs carry only counts (`notes retranscribe segments=… audio_ms=… updated=… failed=…`). Structuring uses the configured clean-up model (off by default when that model is on another host). Speaker labels are on by default and run on the Mac only: audio is never sent for them, names you give a speaker are saved with the note on this Mac, and the one-time model download (from Hugging Face, pinned and checksummed, sending nothing about you) starts by itself in the background. **Turn off** (Notes window or Settings → Notes) stops labelling and cancels the download, and **Remove** deletes the model. Saved voices use the shared server library below. Naming remembers by default while the server-wide switch is on; an unticked Remember voice keeps the name only in the note. The Mac sends bounded clips of settled turns only to its own server for recognition. Existing Keychain voiceprints are imported once to that server, then deleted locally after acknowledgement; failed imports remain for retry.
- **Mac call audio is opt-in and stays on your devices.** With **Include call audio** (Notes toolbar → Sources, or Settings → Notes → Sources; off by default), a Mac Live Notes recording also captures what the Mac plays (every app but Chirp, or one app you pick) through a Core Audio process tap, or ScreenCaptureKit audio when no tap can be made; macOS asks for Screen & System Audio Recording once. Capture runs only while a note records. The call audio is mixed into the same 16 kHz stream that already goes to your own Chirp server; nothing else receives it. It is never logged (logs carry the capture kind and counts only), never written to disk except as the mix under the existing opt-in **Keep audio with notes**, and its speaker labels (You for the microphone, Person N for the call) are computed on the Mac. iPhone and Android cannot record other apps' audio, so there is no equivalent there.
- **Android and iOS speaker labels are on by default. Both keep no voiceprints.** *Label speakers* (Settings → Notes or a note's menu; both respect an explicit off) adds a random per-note session id to each Notes segment sent to your own Chirp server. The server compares the segment's voices with that note's earlier ones using a pinned WeSpeaker model (27 MB, CC-BY-4.0, downloaded from Hugging Face once and checked against its SHA-256; both request it automatically on the first labelled note). The comparison state (per-speaker averages of voice embeddings) lives in the server's memory only unless a voice is saved in the shared library below; it is never logged, never returned to the phone, and dropped after 6 idle hours, past 32 notes or on restart. The server returns who spoke which words and, for recognised voices, the saved name and an opaque voice id; it never returns a voiceprint. The phone stores those turns and the names you give inside the sealed note; logs carry counts and timings only. On Android and iOS, naming suggests names from the server’s saved voices first, then recent notes in the sealed local library. Recent-note names stay on the phone. On iOS, a recognised name has a ✓ and **Not X** clears it only in this note. A one-time notice explains remembering; the server-wide switch stops it, and Forget removes saved voices while keeping names in existing notes. Naming with Remember voice selected saves the name and voiceprint on your own server once there are 20 seconds of speech; the phone sends only a temporary session/generation/speaker reference, never a voiceprint. Phones keep no local voiceprint library; saved voices live on their own server as described below.
- **Saved voices stay on your Chirp server.** Your Chirp server keeps one library of saved voices, shared by every device paired to it, so a person you name on one device is recognised on the others: each saved voice is a name and a voiceprint (a list of 256 numbers computed from that person's speech, not audio). They live in one file on the machine that runs your server, `voices.json` in its data folder (`~/Library/Application Support/Chirp/speakers/` on a Mac), readable only by your user (0600). Nothing is created until a voice is saved. New voiceprints are computed and kept on that machine: devices see names, seconds of speech and dates only. The Mac’s one-time migration sends its legacy Keychain voiceprints only to its own server, then deletes acknowledged items. Audio clips a Mac sends to save or recognise a voice travel only to your own server, over loopback or your tailnet, and are held only for that request. Names and voiceprints are never logged (logs carry counts and codes) and never sent anywhere else; the only outbound requests remain the pinned model downloads. **Remember voices** (Settings → Notes → Saved voices on Mac, Android and iOS, or `chirp-server voices off`) turns storing and recognising off for the whole server; **Forget** deletes one voice and **Forget all voices** deletes the file. Removing the speaker model keeps the voices. If your devices use different Chirp servers, each server has its own library; nothing is synced between them.
- **Android history and learning are local and encrypted.** History and **Learn from my edits** default on for new installs and users who never chose; an explicit history opt-out stays off. Turn them off in Settings → Dictation (history also in Privacy & history). History keeps up to 200 dictations for 7 days by default, excluding password and incognito editors. Learning watches only the inserted field for at most 60 seconds, until focus changes or the next dictation; it ignores unrelated edits, large rewrites and Private sessions. The same correction twice, or **Teach Chirp** in History once, activates vocabulary or a per-package style. Floating-mic learning uses Android 13+ editor-info access to honor incognito flags, and excludes no-suggestions fields. It stays off on Android 12, where that access is unavailable; Chirp Keyboard learning works on every supported version. Learned holds at most 200 items with source edits and Approve / Undo / Delete / Reset app. History and learning use separate Android Keystore AES-GCM keys in credential-encrypted app storage, excluded from backup and device transfer. Clear history leaves learning intact. Active items go only with dictation to your own server and its configured clean-up host, never into logs or diagnostics.
- **Android keeps your notes, on the phone only.** The Live Notes library (on by default; an earlier opt-out stays off) keeps every note until you delete it: one file per note plus an index, AES-GCM sealed with an Android Keystore key in credential-encrypted storage (nothing is written before first unlock), excluded from backup and device transfer, never logged, never indexed by app search and never synced or sent to your computer. There is no Save step. Retention is its own setting ("Delete notes older than": Never by default, 1 year, 90 days or 30 days), apart from dictation history. A deleted note stays in Recently Deleted for 30 days. Turning the library off keeps existing notes; *Delete all notes* removes them and the key. A file that cannot be opened is moved aside, never deleted.
- **iOS keeps a sealed local Notes library.** Notes and their index save continuously under the app's Application Support folder, AES-GCM sealed with the existing device-only `notes-recovery-key` Keychain key and a separate `chirp.notes.library.v1` authentication context. Files are owner-only, excluded from backups and protected with complete iOS file protection; writes may wait for unlock. Legacy recovery records migrate idempotently, marked Recovered, with unreadable records quarantined. Notes never enter Spotlight, logs, or sync. Retention defaults to Never and is independent of dictation history. Deletion moves notes to Recently Deleted for 30 days, with Undo and Restore. An earlier explicit storage opt-out stays off; turning storage off preserves existing notes and stops keeping new changes. Copy, Share and Export Markdown make separate user-chosen copies. The Notes Live Activity can show the note title (up to 60 characters), state and time; it never shows the note body or transcript. **Re-transcribe…** (a stopped note’s More menu or transcript header; gap rows have **Try again**) sends that note’s kept clips only to the paired Chirp server, after a consent sheet every time that names the length, the clip count and the destination, and is hidden when **Settings → Notes → Allow re-transcribing** (on by default) is off. Logs carry only counts (`notes retranscribe segments=… audio_ms=… updated=… failed=…`).
- **Kept audio is opt-in, on all three platforms.** *Keep audio with notes* (Mac, Android and iOS, off by default) keeps each spoken segment of a note as a short AAC clip (mono, about 32 kbps) in the note's own folder, with its start offset, duration and sample rate so a later re-transcribe can rebuild the transcript. Android segments are contiguous and keep quiet frames within each segment; paused time is not recorded. On Android and iOS clips are sealed with the notes key and decrypted only in memory to play; on the Mac they are `0600` files like the note itself. The total is shown in Settings → Notes, and audio is removable per note or all at once (the text stays). Kept audio is never automatically uploaded. On the Mac, Android and iOS, **Re-transcribe…** sends a note’s kept clips to the paired Chirp server only on request, after a consent sheet each time, over the same authenticated socket (#287); **Allow re-transcribing** turns the action off. Android decrypts and decodes AAC only in memory, preserves speaker assignments and body edits, and stores one previous transcript inside the sealed note for Undo/Restore. iOS opens each sealed clip and decodes it in memory (no plaintext file), keeps names, turn reassignments and body edits, stores one previous transcript inside the sealed note, and pauses a run after the clip in flight when the app leaves the foreground. Turning the setting off cancels a run on Android and iOS.
- **Server re-transcription has the same privacy rules as live audio.** `start.retranscribe: true` sends one kept clip to the paired Chirp server for in-memory recognition, with previews disabled. No audio or transcript files are written unless the operator explicitly enabled debug retention; `ready.debug_retention` still exposes that exception. Only transcript text can go to the configured clean-up endpoint. Logs contain the existing session id, byte counts, levels and timings, never transcript, context, note title or destination. Device activity records `notes_retranscribe`, audio duration and outcome only. There is no new destination, automatic upload or server-side consent bypass.
- **Device activity stays on the server machine, and you can turn it off.** The server keeps a short list of requests so Settings → Devices can show which of your devices used it: the time, which device (its pairing id, or "This Mac" / the shared token), the client kind (`mac`, `android`, `ios`, `desktop`), the kind of request (dictation, notes segment, notes re-transcription, transcribe, notes clean-up, organize, voice edit, speaker model), the clean-up style id, how long it took, the audio length, whether clean-up ran and an outcome code. Refused requests are only counted, per reason and revoked device, with the last time. It never holds what was said or written (no transcript, audio, prompt, learned item, outline, selection, character count or session id), nor an IP address, a `Tailscale-User-*` identity, a token or its digest. It is a `0600` file, `device-activity.json`, beside the server state (`~/Library/Application Support/Chirp/` on a Mac), so it survives a restart; it keeps at most 5000 events for 30 days (`[activity] max_events`, `max_days`). It is never logged and never sent anywhere. Only the owner can read it: a separate `~/.config/chirp/owner-token` (`0600`, never in a pairing link or QR code, and accepted by no other endpoint), presented from this machine directly, never through `tailscale serve`; phones, even with the shared token, get 403. **Keep device activity** in Settings → Devices (or `[activity] keep = false` in `server.toml`) stops recording and deletes everything stored.
- **Debug retention is opt-in, local and loud.** With `--debug-retain`, WAV + transcript files are written under `~/Library/Application Support/Chirp/debug/`, expire after three days, and every client shows a persistent red warning.
- **Tailnet-only exposure.** The server binds to loopback (`127.0.0.1:7821`). Publishing it for a phone uses `tailscale serve` (your private tailnet, TLS from the tailnet certificate), never the public internet: the Mac's **Pair a Phone** refuses to pair while Funnel is on.
- **Bearer pairing.** Clients authenticate with a token your Chirp server generates: the shared one at `~/.config/chirp/token` (mode 0600), or a named per-device token from `chirp-server pair --name`, revocable with `chirp-server devices revoke` (the server stores only a SHA-256 digest). The pairing QR/link is shown locally only; treat it as a secret. Audio is rejected before authentication succeeds.
- **Clean-up stays on your computer** (the machine that runs your Chirp server) in `managed` mode (a local MLX model, forced offline). If you deliberately point correction at an external OpenAI-compatible endpoint, clients label the feature "sends text to \<host\>". Audio never leaves your computer; only the final text can, and only then.
- **The phone's own recogniser is opt-in and labelled.** Android's *Use this phone's recogniser* setting (off by default) lets the keyboard dictate while the computer is unreachable using Android's on-device speech service from Google or the phone maker, not Chirp's engine. Android documents that recogniser as on-device, but it is a third-party service under its own terms. An **on phone** chip shows every time it is used. See [Android → When your computer is unavailable](../android/README.md#when-your-computer-is-unavailable).
- **The Android floating mic never copies on its own.** It reads only the focused field's text and selection, with the existing event types and permissions. On Android 13+, the editor-info flag lets it honor incognito fields for learning without changing your keyboard. Words it can't put in the field wait in its panel and are cleared on Done, ✕, screen off or after 2 minutes. Copy is always your tap, and the clip is marked sensitive (Samsung's clipboard history may still keep it). The bubble's saved position is an edge and a height per screen, never text or app names. "Hide in this app" lasts only until you leave that app.
- **Phone diagnostics are content-free.** Android and iOS keep per-session timings (numbers, booleans and fixed enum names only), and Android message-free crash frames; no text, audio, URLs, hosts, tokens or app names.

- **Keeping your Android keyboard is optional.** The input-mode choice and floating-mic skip are ordinary, non-sensitive preferences. Choosing either mode never grants or revokes system permissions. The Accessibility guide discloses focused-field access before opening Android settings; passwords are excluded, field text stays local and is never logged or saved. The service keeps its four event types and 100 ms timeout without additional window-retrieval flags, key-event filtering or an overlay permission. It hides while Chirp Keyboard is selected. Advanced Protection is queried through a normal permission, not bypassed. Notes and Scratchpad work without Accessibility.

### Quick dictate, Speak buttons, widgets and text sharing (Android)

The Dictate tile and widget deliberately **copy the final automatically** so it can be pasted into any app. These are the only dictation paths that auto-copy. Use raw re-copies the original. Every copy sets Android’s `EXTRA_IS_SENSITIVE`; that hides supported clipboard previews, but Samsung’s clipboard history may still retain it. The floating mic copies only after an explicit Copy tap. [Android clipboard privacy](https://developer.android.com/develop/ui/views/touch-and-input/copy-paste#sensitive-content).

A Speak-button request receives only its single final and an unavailable-confidence marker through `RECOGNIZE_SPEECH`’s Activity result. It does not receive history, other notes or clipboard content, and this mode never auto-copies. The requesting app controls what happens to that result. Speech still goes to your paired Chirp server even when the caller supplies an offline preference. Dictation history is on by default on Android (an explicit off choice stays off): clipboard sessions use “Quick dictate”; Speak sessions use the requesting app’s label when available.

The launcher widget contains static controls only: no note text, dictated words or periodic refresh. Quick dictate is excluded from Recents, disables its screenshot thumbnail where supported, and cancels microphone/network work when left. Scratchpad hand-off is a one-use, expiring in-process value, never a text Intent extra, preference, log or notification.

Plain-text shares into Notes are saved in the existing sealed, local library or appended as the user’s own edit to the same recording/paused note. Sharing alone makes no speech-server request. The text is sent for processing only if the user later chooses Organize. Oversized and non-text shares are refused. The receiver does not return any library data to the sharing app.

## Linux and Windows desktop Notes

Desktop Notes stores text documents and an index locally under the app's per-user
data directory. Linux uses private 0700 folders and 0600 files; Windows verifies a
protected user + SYSTEM ACL before writing note content. These files are not
encrypted, synced or registered with a desktop search index. Notes stay until you
delete them; Recently Deleted keeps them for 30 days unless explicitly emptied.
Export Markdown writes a separate file to the destination you choose.

The desktop streams microphone audio only to your paired Chirp server. It does
not keep audio on disk. Optional smart notes sends each completed transcript to
the same server's configured cleanup model; Organize sends the notes text there.
The server's existing debug-retention and cleanup endpoint settings still apply.
The app reports debug retention when the server advertises it. Tokens stay in
the system credential store; note text, audio and credentials are never logged.
